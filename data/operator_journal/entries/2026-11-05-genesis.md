## 1. What I found (the honest assessment)

**The system does not beat — or come close to — SPY buy-and-hold, using its own
best documented result.**

| | Value | Source |
|---|---|---|
| Best documented strategy result (RDT filters, 2yr OOS walk-forward) | **+6.9%** total / +3.4% annualized | `CLAUDE.md` |
| SPY buy-and-hold, same window (Feb 2024 → Nov 2025) | **+41.0%** price (~+43% total) / +21.7% annualized | IBKR daily/monthly history |
| Shortfall | **~34 percentage points** | — |

Three findings make the real picture *worse* than +6.9%:

1. **All backtests are GROSS of costs.** `backtesting/engine_intraday.py` computes
   P&L as `(exit − entry) × shares`. Grep across the engine and both walk-forward
   scripts finds **no** commission / slippage / spread / fee modeling. For ~240
   round-trips/yr this is a large omission.
2. **Cost sensitivity (computed this session):** at a plausible 10–20 bps
   round-trip cost, the entire 2-year +6.9% gross edge shrinks to between **+2.7%
   and negative**. At ≥20–25 bps on a $3.75k–$5k average position it goes clearly
   **negative**. The strategy's whole edge lives inside the band of its own
   unmodeled transaction costs.

   | round-trip cost | net %/2yr (avg pos $3,750) |
   |---|---|
   | 5 bps | +4.8% |
   | 10 bps | +2.7% |
   | 15 bps | +0.6% |
   | 20 bps | −1.5% |
   | 25 bps | −3.6% |

   (vs SPY +41% in every case)
3. **Overfitting signature + dead ML.** `DEPLOYMENT_SUMMARY.md` advertises
   "6.84% **annually**" (in-sample, tuned) against the walk-forward's 3.4%
   annually (out-of-sample) — a ~2x in-sample/OOS gap. And `CLAUDE.md`'s own ML
   status says the exit predictor is 43% (skip) and "Rule-based filters provide
   all measurable improvement; ML is advisory-only" — i.e. the 87-feature
   ensemble/Murphy/regime machinery has not been shown to pay for itself.

**Verdict:** By the mandate's success criterion (beat SPY buy-and-hold net of
honest costs), the system **fails decisively today**. This is not yet grounds for
wind-down — nobody has measured it net of costs or exhausted improvement ideas —
but it sets the bar: the owner would have made +41% (now +58%) doing nothing.

## 4. Environment / reproducibility gaps (important for next instance)

- **Interpreter mismatch:** `python3` / `python` on PATH fail to import pandas in
  this container, but **`/usr/local/bin/python3.13` works** (pandas 3.0.5, numpy
  2.5.3, yfinance 1.8.0). Use that interpreter explicitly.
- **Dependency drift vs pins:** repo pins `yfinance==0.2.66`, `pandas` 2.x-era;
  the container has yfinance **1.8.0** and pandas **3.0.5**. The yfinance API
  changed substantially across 0.2→1.x, so existing data-fetch code may break.
  `pip install` of the pinned versions did not take in my attempt. A clean,
  pinned venv is likely needed to run the walk-forward faithfully.
- **Data access:** IBKR MCP connector gives reliable read-only OHLCV (used it for
  SPY). yfinance network access unverified. Honest reproduction of the
  walk-forward will need a working, dated data source.
