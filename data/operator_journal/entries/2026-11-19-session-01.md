## 2. Assessment of profitability (the mission)

I could not run the full walk-forward backtest this session (yfinance is
rate-limited behind the proxy; the repo's full import stack needs deps not installed;
the live DB/container is not reachable by design). So I assessed with: the repo's own
claimed numbers, a read of the actual accounting code, and **real SPY data from the
IBKR MCP tool**.

**Finding A — the bot loses to buy-and-hold by ~5×, even gross.**
- Bot's best config ("RDT Filters", per `CLAUDE.md`): **+6.9% over ~21mo, 3.4%/yr**, gross.
- SPY buy-and-hold, same window (Feb 2024→Nov 2025), real IBKR closes
  508.08→683.39: **+34.5% price / ~+36.7% total return, ~18.5%/yr.**

**Finding B — the backtest applies ZERO transaction costs**, so even the 6.9% is
overstated:
- `backtesting/engine_enhanced.py` computes P&L as pure `(exit−entry)×shares`; no
  commission/slippage anywhere.
- `scripts/run_backtest.py::apply_slippage()` is a no-op that returns data unchanged
  while the banner claims "0.1% slippage."

**Finding C — net of honest costs** (~0.115% round-trip, conservative), the claimed
+$1,716 gross shrinks to **+$182 … +$1,102** (≈0.4%–2.5%/yr) depending on average
position notional; at the larger sizes a $25K/8-position account actually uses, costs
eat ~90% of the edge.

**Finding D — development is drifting away from the mission.** The most recent commit
is a "SaaS product overhaul" (landing/pricing/login/register/onboarding). The core
product loses to an index fund net of costs; productizing it is premature.

Full reasoning and tables: `POST_MORTEM_RRS.md`.

## 3. What I changed (code)

**Wired an honest transaction-cost model into the backtest engine** so that "net of
honest costs" — the mission's own standard — becomes *measurable* instead of
silently zero. This is the single highest-leverage, lowest-risk change available: it
does not alter the strategy, only makes its evaluation truthful.

- `backtesting/engine_enhanced.py`:
  - New constructor params `commission_per_share=0.005`, `slippage_bps=5.0`
    (set both to 0.0 to recover old gross numbers).
  - New `_fill_cost(shares, price)` helper; `self.total_costs` accumulator.
  - Costs deducted from `capital`, `total_costs`, and the trade's `pnl` at **every**
    fill: base entry (`_enter_position`), scale-out (`_scale_out`), and final close
    (`_close_position`).
- `scripts/run_walkforward_v2.py`:
  - Applied the same entry cost in the v2 `_enter_position_filtered` override (the
    only entry path not routed through the base engine). All exit paths already route
    through the base engine's methods, so they are covered.

Since final return derives from `self.capital`, deducting at each fill makes the
headline total return net-of-cost automatically.
